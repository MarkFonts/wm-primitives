Ramps

One curve, three channels. The alpha of a scrim, the colour of a blend and the radius of a blur are the same cubic Bézier applied to different quantities — so the package has one sampler and three emitters rather than three engines. Every gradient on this page is a string src/gradient.ts emitted; none of it is typed in.

The curve cubic-bezier(0.416, 0.657, 0.695, 1)

Two CodePens make the same fade by hand, seven stops written out one at a time. Fitting a cubic-bezier() to those seven numbers lands within 0.0012 of every one of them, RMS 0.00071 — about a third of one step in 8-bit. The hand-written version and the curve are the same fade, so the clothoid is a preset here, not a code path. The white dots are where the eight default stops fall: they crowd toward the transparent end, because the curve is sampled by its own parameter rather than at even positions.

The edge why linear will not do

Interpolate alpha in a straight line and it does not read as straight: perceived lightness moves fastest at the transparent end, so the fade announces itself where it starts and then crawls. Both panels fade the same colour over the same text across the same distance. Only the curve differs. This is the whole argument for the file.

Where you mix the midpoint, four spaces

The received wisdom is that oklab rescues a gradient from the grey midpoint sRGB gives you. It does not. A straight line between opposite hues passes through the neutral axis in any rectangular space, because that is where the axis is. What oklab buys is even lightness. Only oklch holds the chroma, by interpolating hue as an angle and going around rather than through — at the cost of a hue nobody picked. The default stays oklab because it is the predictable one.

Steering a channel Mass Driver's schema

One curve on the interpolation re-spaces the stops along a fixed path through colour space. A curve per channel moves the path itself. Below left: the same two colours with one channel steered at a time — the ramp leaves the straight line between its endpoints, which is how the tool escapes sRGB's mud without changing space. Below right: the three graphs for #F65030 → #3050F6, plotted on each channel's own axis. R falls, B rises, and G does not move at all — which is why that pair never goes grey, and why a curve on G there does nothing.

variablur's effect, as a stack of masked backdrop layers. Each layer owns one band at full opacity carrying that band's absolute radius — not a cumulative stack, which ghosts: backdrop-filter blurs what is behind the layer, so at partial mask alpha the compositor blends a blurred copy over the still-sharp original and live text shows a double image. Bands are evenly spaced; only the radius follows the curve. The right-hand panel holds the first lines with start, because the smallest stop in the stack still lands inside the first line's ascenders otherwise.

It blurs pixels; it does not redact. The words stay in the DOM — selectable, copyable, findable, and read aloud in full by a screen reader, which sees no blur at all. Never use it to withhold anything.

Banding 8-bit, and what the engine cannot fix

A ramp crossing ~94 of the 256 available levels over 190px spends about two pixels per level, and the eye finds those edges. More stops cannot help — an 8-stop ramp and a 2-stop ramp band identically. Nothing in CSS asks for more output bits, so sub-level noise is the only control there is, and every band on this page carries it.

Mostly you do not need it: Skia already dithers a background gradient and very nearly does not dither a mask — the same ramp measures a per-pixel deviation of 2.98 as background-image against 0.22 as mask-image. So a scrim is dithered for you and a mask over a flat ground is not, which is the one place in this package that bands.
